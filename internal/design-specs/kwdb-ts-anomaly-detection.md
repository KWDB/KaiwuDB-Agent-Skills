# Kwdb-TS-Anomaly-Detection 功能规格书

## 1. 概述

### 1.1 技能名称
`kwdb-ts-anomaly-detection`

### 1.2 技能定位
自动化端到端的时间序列异常检测技能，用于 KWDB 时序数据库业务时序数据分析。

### 1.3 核心功能
通过对 KWDB 时序数据进行统计分析，自动识别异常点（outliers），并生成可读的检测报告。

### 1.4 适用场景
- 检测传感器指标（sensor metrics）中的异常
- 分析物联网遥测数据（IoT telemetry）中的异常
- 监控数据（monitoring data）的 spikes、dips、drift 检测
- 时序表中异常点（abnormal points）或数据质量问题的识别
- 当用户提及以下关键词时触发：
  - "anomaly detection"、"find anomalies"、"detect outliers"
  - "3-sigma check"、"STL decomposition"、"time-series anomaly"
  - 传感器数据检查、IoT 数据验证、异常值标记等

## 2. 功能规格

### 2.1 异常检测方法

#### 2.1.1 3-Sigma 法则
- **原理**：基于数据的均值和标准差，计算置信区间上界（mean + 3σ）和下界（mean - 3σ）
- **改进**：结合 STL（Seasonal-Trend decomposition using Loess）时间序列分解
- **作用**：去除季节性趋势后，在残差上应用 3-Sigma 检测，消除正常周期性波动的影响

#### 2.1.2 周期自动推断
脚本自动根据时间戳间隔推断采样频率和推荐周期：

| 时间戳间隔 | 识别频率 | 推荐周期 |
|-----------|---------|---------|
| ≤ 60 秒 | 分钟 | 60 |
| ≤ 3600 秒 | 小时 | 24 |
| ≤ 86400 秒 | 日 | 7 |
| ≤ 7 天 | 周 | 4 |
| ≤ 30 天 | 月 | 12 |
| > 30 天 | 未知 | 7 |

#### 2.1.3 数据量要求
- **最小要求**：STL 分解至少需要 `2*period + 1` 个数据点
- **默认情况**：日数据（period=7）需要至少 15 个点
- **超时限制**：单次查询数据量上限为 **100,000 条**

### 2.2 目标数据要求

#### 2.2.1 数据库类型
- 目标数据库必须为 **TIME SERIES** 类型
- 非时序数据库将触发永久终止

#### 2.2.2 数据列类型
- 支持检测的列类型：`INTEGER`、`FLOAT`、`DOUBLE`
- 时间戳列：`TIMESTAMP`
- 标签列：主标签用于分组，辅助标签用于过滤
- **所有被检测的列必须为数值类型**，否则触发终止

#### 详细步骤说明

| 步骤 | 名称 | 描述 |
|------|------|------|
| **0** | 安全确认 | **强制**显示安全警告，确认用户授权 |
| **1** | 前置验证 | 验证脚本可用性、收集连接参数、测试连接、确认目标表和列 |
| **2** | 意图分析 | 分析用户意图，生成 SQL 查询，验证元数据 |
| **3** | 数据库校验 | 确认目标库为时序库，所有过滤列为数值类型 |
| **4** | 主标签处理 | 若指定主标签值则直接处理；若未指定则遍历所有主标签 |
| **5** | SQL 优化 | 保留时间戳和数值列，添加 ORDER BY 和 LIMIT |
| **6** | SQL 封装 | 将优化后的 SQL 作为子查询，外层 ORDER BY ASC |
| **7** | 展示 SQL | 向用户展示最终 SQL 并等待确认 |
| **8** | 数据量校验 | COUNT 查询检查数据量，超限则终止 |
| **9** | 执行查询 | 通过脚本执行 SQL，结果保存到 `/tmp/` |
| **10** | 结果验证 | 验证结果文件非空，否则终止 |
| **11** | 异常检测 | 运行 `3-sigma-detection.py` 执行 STL+3σ 检测 |
| **12** | 加载列规则 | 从列注释中提取验证规则 |
| **13** | 规则过滤 | 移除未违反声明规则的异常点 |
| **14** | 报告生成 | 根据用户选择的格式生成报告 |
| **15** | 清理 | 删除临时文件，保留最终报告 |

## 3. 检测限制

### 3.1 硬性限制

| 限制项 | 限制值 | 说明 |
|--------|--------|------|
| 最大数据量 | 100,000 条 | 单次查询超过此值时终止任务 |
| 最小数据量 | 2×period+1 | STL 分解所需最小点数 |
| 检测方法 | 3-Sigma | 仅支持基于 STL 残差的 3σ 检测 |
| 执行脚本 | kwdb_sql_execute.py | 所有 SQL 必须通过此脚本执行 |

### 3.2 数据范围限制

- **不支持**跨多个数据库的联合检测
- **不支持**跨多个表的联合检测
- **不支持**实时流数据的异常检测
- **仅支持**对已有历史数据的离线分析

### 3.3 禁止行为

- ❌ 使用 `kwdb-mcp-server` MCP 工具执行 SQL
- ❌ 创建或删除数据库/表
- ❌ 向表中写入或修改数据
- ❌ 修改或绕过预定义的终止规则
- ❌ 虚构非必要的操作或任意扩展任务
- ❌ 截断中间输出
- ❌ 在元数据查询时保存结果到文件

## 4. 错误处理

### 4.1 错误分类

| 错误阶段 | 错误类型 | 处理方式 |
|----------|----------|----------|
| 前置条件 | 脚本未找到、连接失败、参数缺失 | 永久终止 |
| 验证阶段 | 非时序库、无数值列、元数据不存在 | 永久终止 |
| 检测阶段 | 数据不足、JSON 解析错误、周期推断失败 | 报告错误，备选方案 |
| 报告生成 | PDF/HTML 生成失败 | 回退到 Markdown |

### 4.2 终止条件

当以下任一条件满足时，任务**永久终止**：

| 步骤 | 终止条件 |
|------|----------|
| 1.1 | `scripts/kwdb_sql_execute.py` 不存在 |
| 1.2 | 用户未提供必需连接参数 |
| 1.3 | 数据库连接测试失败 |
| 2 | 用户指定的数据库/表/列不存在 |
| 3 | 目标库非时序库，或所有过滤列为非数值 |
| 4 | All Tags 模式下 `SELECT DISTINCT` 返回空 |
| 8 | 数据量超过 100,000 条 |
| 10 | 结果文件为空（Single Tag）或所有标签均无数据（All Tags） |

## 5. 输出规格

### 5.1 报告格式

| 格式 | 说明 | 输出位置 |
|------|------|----------|
| Direct | 直接打印到控制台 | 屏幕 |
| Markdown | `.md` 文件 | `/tmp/dt-report-<timestamp>.md` |
| HTML | `.html` 文件 | `/tmp/dt-report-<timestamp>.html` |

### 5.2 报告内容

每个主标签（Primary Tag）包含：

- **基本信息**：数据库名、表名、检测时间、数据时间跨度
- **检测规则**：检测方法（3-Sigma）、列注释规则
- **统计摘要**：总行数、3σ 异常点数、规则过滤后最终异常点
- **阈值信息**：上界、下界、计算周期
- **异常详情表**：序号、时间戳、值、违反的规则（如有）

### 5.3 临时文件管理

- SQL 执行结果：`/tmp/sql-result-*`
- 检测结果：`/tmp/detect-result-*`
- 中间 JSON：`/tmp/report-json-*`
- 最终报告：`/tmp/dt-report-*`

任务完成后自动清理所有临时文件，仅保留最终报告。

## 6. SQL 执行规范

### 6.1 执行方式
```bash
python scripts/kwdb_sql_execute.py <host> <port> <username> <password> "<sql>" [output_file]
```

### 6.2 元数据查询规则
- **不指定**输出文件时，结果仅打印到标准输出
- **指定**输出文件时，结果保存到 `/tmp/` 目录

### 6.3 SQL 模板
```sql
-- 最终封装的异常检测 SQL
SELECT * FROM (
    <用户生成的或优化的 SQL>
) AS anomaly_subquery ORDER BY <timestamp_column> ASC
```

## 7. 依赖项

### 7.1 必需脚本
- `scripts/kwdb_sql_execute.py`：SQL 执行脚本

---

## 8. 安全考虑

### 8.1 凭证处理
- 数据库凭证（用户名、密码）为敏感信息
- 仅在内存中使用，不持久化到磁盘
- 凭证仅通过命令行参数传递，不写入配置文件

### 8.2 权限要求
- 执行异常检测前必须获得用户明确授权
- 建议在隔离环境中执行

---

## 9. 性能考量

### 9.1 数据量控制
- 默认 LIMIT 1000（无时间过滤时）
- 超过 100,000 条时拒绝检测，建议降采样

### 9.2 周期推断
- 自动推断，无需用户指定
- 推断失败时默认使用 period=7
